Contexte · brouillon

Thomas agit avec les objets de l’exploitation.

Avant une tâche, une observation ou un réglage, l’orchestrateur charge le contexte de la ferme. Il reconnaît un nom, un alias ou un mot-clé. Il propose une carte. L’écriture attend la confirmation.

La V2 charge déjà les parcelles, les sous-parcelles, le matériel, le personnel, les conversions, les clients, les fournisseurs et les produits. Elle ne charge pas encore les prix de vente, les plans de culture ni les durées de pousse. La V3 les ajoute, parce qu’une tâche et une observation s’y adossent.

Parcelle

Table plots. Le lieu principal de l’exploitation. Thomas ne crée pas une parcelle au milieu d’une déclaration de temps. Il la crée seulement quand le message est un réglage.

ColonneRôle
name, aliases, llm_keywordsReconnaissance dans le chat. Le mot-clé par défaut est le nom en minuscules.
typeSerre plastique, serre verre, plein champ, tunnel, hydroponie, pépinière, autre. Défaut autre si le type dit n’est pas reconnu.
length, width, surface_areaDimensions en mètres. La surface est le produit des deux quand elles sont dites, ou reprise de la géométrie carte si confirmée.
geometry (GeoJSON / polygone)Contour sur le plan / carte de la ferme (satellite). Optionnel. Source de vérité spatiale dès qu’il est renseigné — voir Carte de la ferme.
standard_bed_width, edge_safety_margin_cmPréférences par défaut seulement. La disposition réelle (largeur, inter-planche, nombre) est celle du plan de culture — voir Planification.
is_activeSeules les parcelles actives entrent dans le contexte.

Ajoute une serre plastique, Serre 2, 8 mètres sur 30, avec 10 planches.

Thomas propose une carte de réglage. Après confirmation, il écrit plots. Les « 10 planches » sont une disposition initiale pratique, pas un plafond physique pour toujours. Une culture ultérieure pourra redécouper la même serre autrement (voir disposition flexible en planification).

Ouvre le plan de la ferme et dessine la serre 2.

Thomas bascule le dashboard sur la carte satellite, centre la ferme, et propose le mode dessin. La forme fermée crée ou met à jour la parcelle (geometry, surface / dimensions proposées).

Modifie l’adresse de la ferme et recentre la carte.

Réglage sur farms (nom, adresse, centre / emprise). Après confirmation, le fond satellite recentre. Modifier une forme déjà posée (sommets, déplacement) met à jour la géométrie sans recréer la parcelle. Cahier détaillé : Carte de la ferme.

Sous-parcelle

Table surface_units. Nom produit : sous-parcelle. Le type par défaut est planche. Elle a un nom, un code, un numéro d’ordre, des alias, des mots-clés, une longueur, une largeur et une surface.

Pour le temps et les observations, Thomas rattache les noms reconnus aux sous-parcelles du plan ouvert (disposition active). Un nom inconnu ne crée pas une géométrie au vol pendant une déclaration de temps : il demande, ou renvoie vers la planification si l’agriculteur veut changer le découpage.

Matériel

Table materials. Tracteur, outil de tracteur, outil manuel, matériel de vente, petit équipement, ou autre. Le chat le reconnaît par name et llm_keywords.

ColonneRôle
name, category, custom_categoryIdentité. Le nom est obligatoire pour un ajout.
brand, model, supplierPrécisions facultatives.
cost, purchase_date, condition_notesAchat et état. Ce n’est pas le prix de vente d’un légume.

Une tâche range les matériels reconnus dans tasks.material_ids. « J’ai passé le tracteur » rattache le tracteur déjà connu. « Ajoute un tracteur John Deere » est un réglage : il écrit materials, pas une tâche.

Personnel · décidé

Table farm_members, reliée à profiles pour le prénom, le nom et le nom complet. Rôles : propriétaire, responsable, employé, conseiller, lecteur, stagiaire. Seuls les membres actifs sont proposés.

Sur une tâche, un prénom reconnu devient une ligne task_members, rôle participant. tasks.number_of_people compte l’effectif (décimal). Si le message dit « avec Marie et Paul » et que seul Marie est membre, Thomas rattache Marie et annonce que Paul n’est pas dans l’équipe.

Inviter quelqu’un se fait depuis le chat et depuis l’écran Personnel. « Ajoute Paul comme employé » propose une carte d’invitation. Après confirmation, Thomas génère un lien d’invitation à envoyer (WhatsApp ou autre canal choisi par l’agriculteur). Paul crée son compte en ouvrant le lien.

En plus des invitations nominatives, chaque ferme a un lien permanent (QR code imprimable) pour les stagiaires et les arrivées courtes. Scanner le QR ouvre la création de compte rattachée à la ferme. Le responsable peut révoquer ou régénérer ce lien.

Prix des légumes

Deux grilles, distinctes du prix dit au moment d’une vente.

TableCe qu’elle fixe
prix_ventePrix d’une culture (cultures), par canal : vente directe, restauration, marché, panier, grossiste, magasin bio, coopérative, autre. Unité et part des ventes.
product_sale_pricesPrix d’un produit vendu (products), par canal, avec une fenêtre de semaines facultative.
user_conversion_unitsListe des équivalences. Elle convertit l’unité dite en unité conventionnelle. Elle ne fixe pas le prix. Le détail est dans Unités.

Le chat V2 n’a pas d’outil pour modifier la grille. Une phrase « les tomates sont à 3,50 € le kilo en vente directe » est un réglage de prix_vente. Thomas propose la carte, puis écrit la grille après confirmation. Une phrase « j’ai vendu 2 caisses de tomates à 20 € » est une vente : elle écrit la facture avec le prix dit, et elle ne change pas la grille. Si la caisse de tomates est dans la liste, la facture montre aussi les kilogrammes.

Unités

L’unité retenue est celle de l’agriculteur. Une caisse, une grande caisse, un cageot, une brouette, un sac, un épandeur, une cuve, un pulvé. La tâche, la vente ou l’intrant garde cette quantité dans quantity_value et quantity_unit. À côté, la liste user_conversion_units donne l’équivalent conventionnel : kilogramme, litre, ou pièce. Quand la ligne existe au moment de confirmer, Thomas remplit aussi quantity_converted_value et quantity_converted_unit. La liste reste la référence. Une quantité déjà enregistrée s’affiche convertie dès que la ligne existe.

Chaque ligne est partagée par la ferme. Elle dit : un contenant, ce qu’il contient, une valeur, une unité. La colonne crop_name porte ce contenu, culture ou intrant. container_name est le nom dit, pour distinguer une caisse d’une grande caisse. container_type range la famille quand elle est reconnue : caisse, panier, sac, seau, bidon, brouette, pulvérisateur, épandeur, ou autre. Une cuve ou un cageot gardent leur nom, avec le type autre.

Thomas cherche la ligne avant d’enregistrer. Si elle existe, la carte montre les deux quantités : 3 caisses de laitue, soit 18 laitues. Si elle n’existe pas, il ne choisit pas le nombre. La carte de l’action reste confirmable dans l’unité dite, et une seconde carte propose la conversion. La question est sous cette carte : combien dans une brouette de fumier, en kilogrammes. L’agriculteur clique une valeur ou l’écrit. Confirmer la carte écrit la ligne. Le prix, lui, reste sur sa grille.

La liste s’ouvre depuis le panneau, entrée Conversions, dans Ressources. On y relit et l’on corrige les lignes de la ferme.

Planification

Le calendrier, la pousse, les itinéraires, les variétés, les tâches projetées, les débouchés de la semaine et la rotation viennent de Basil. La définition est dans Planification.

Pour une tâche ou une observation, Thomas lit le plan de l’année sur la parcelle : culture, variété, itinéraire, semaines, et semis ou plantation déjà faits. La durée de pousse retenue est celle du plan, sinon de la variété, sinon de l’itinéraire, sinon du catalogue crops.

J’ai désherbé les tomates de la serre 1 pendant une heure avec Marie, au tracteur. Ajoute aussi une planche 4 dans cette serre.

Deux cartes. La première est une tâche : désherbage, 1 h, tomate, serre 1, Marie si elle est membre, tracteur s’il est connu, plan de tomates vérifié. La seconde est un réglage : sous-parcelle Planche 4 sur la serre 1. Chacune se confirme seule.

Le schéma est sur la page « 05 Contexte » du fichier Figma. Chaque action a son écran sur la page « 06 Écrans ».

Chargement du contexte · décidé

On ne charge pas tout le catalogue à chaque message. Le parcours retenu est un index mince, puis hydratation :

  1. Le code charge un index léger : noms, alias, mots-clés des parcelles, cultures ouvertes, matériel, membres, clients — pas les géométries, pas toutes les sous-parcelles, pas tout l’historique.
  2. Jev (ou le match) rattache le message à ces candidats.
  3. Seulement pour les identifiants retenus, le code charge le détail : sous-parcelles, plan ouvert, prix utiles, conversions citées.

Identifier d’abord les mots du message puis chercher dans le catalogue échoue quand le lieu n’est pas dit (« j’ai désherbé les tomates ») ou quand le surnom diffère. Charger tout le catalogue puis matcher est trop lourd. L’index mince garde la qualité du match et la vitesse.

Clients · décidé

Régler un client depuis le chat est possible. En pratique, on le fait surtout dans le registre dédié, après coup. Le chat reste utile pour une vente qui cite un client inconnu : Thomas peut proposer de l’ajouter, sans l’imposer.

Nom ambigu · décidé

Si plusieurs objets matchent, Thomas ne choisit pas en silence. Il demande une précision sous la carte, signale l’ambiguïté, et propose soit de préciser lequel, soit de renommer pour lever le conflit.

Décidé

C1. Index mince → match → hydrater sous-parcelles et plans des objets retenus. Pas tout le catalogue.
C2. Invitation chat + écran Personnel, lien à envoyer (WhatsApp etc.), plus QR / lien permanent pour stagiaires.
C3. Client réglable dans le chat ; usage principal = registre après coup.
C4. Ambiguïté → demander, proposer précision ou renommage.
