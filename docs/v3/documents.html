Documents & pièces jointes · décidé

Joindre, classer, extraire. Confirmer avant d’écrire.

Thomas V3 traite les fichiers comme le reste : agent-first. L’agriculteur envoie une photo, un PDF ou une liste ; Thomas propose une carte confirmable, range le fichier, et n’écrit les données structurées qu’après confirmation. Ce n’est pas un drive générique ni un clone du module Documents Desktop V2.

Principe. Deux couches : (1) pièce jointe liée à une action / un objet (observation, tâche, facture, analyse) ; (2) document de ferme dans le registre Documents, consultable, filtrable, réutilisable. Un même fichier peut être les deux (ex. PDF d’analyse = fichier stocké + ligne analyse de sol).
Décidé · entrée conversation. Tout élément ajoutable au chat (photo, PDF, CSV, capture…) est un document / pièce jointe au sens produit. Il n’y a pas de canal parallèle « import magique » hors pipeline de confirmation.

Pipeline de traitement · décidé

  1. Réception — fichier uploadé dans le storage de la ferme ; empreinte / métadonnées (nom, mime, taille, auteur, date).
  2. Classification — le code + Jev (borné) proposent un type : image générique, PDF générique, analyse de sol, facture / bon, liste de prix, autre document. Le LLM aide à lire le contenu si besoin ; il ne décide pas seul des droits ni de l’écriture.
  3. Extraction (si utile) — champs structurés proposés sur la carte (parcelle, dates, montants, NPK, lignes de prix…). Champs incertains marqués ; l’agriculteur corrige avant confirmation.
  4. Carte confirmable — aperçu fichier + type + champs + destination (Sol / Ventes / Prix / Documents seuls / pièce jointe observation).
  5. Écriture — après confirmation : objet métier (si prévu) + document de ferme et/ou pièce jointe. Sans confirmation : rien n’est écrit côté données structurées ; le fichier uploadé peut rester en quarantaine temporaire puis être purgé, ou rangé en « autre » si l’utilisateur le demande.
Pas d’écriture silencieuse. Une extraction ne met jamais à jour la grille de prix, une facture ou une analyse sans carte confirmée. Même règle que le temps et les observations.

3 · Analyse de sol (PDF ou image)

Aligné sur Sol. Un bulletin labo est souvent dense : texture, calcaire, pH, MO, CEC, majeurs, oligos, parfois ETM / CE. Le fichier nourrit une carte analyse avec tous les postes détectés (valeur + unité + méthode si lisible) — catalogue complet côté Sol, stockage creux. Parcelle, dates, labo, référence, profondeur si présents. Après confirmation : enregistrement + document analyse-sol.

Voici le PDF du labo pour la serre 1.

  1. Thomas classe « analyse de sol », rattache Serre 1 si dit ou proposé.
  2. Il extrait chaque poste lu (pas seulement NPK) ; les cases douteuses restent éditables ; rien n’est inventé pour les postes absents.
  3. Confirmation → analyse complète + document. Le besoin NPK reste un outil séparé (règle de trois), pas une invention à partir du PDF.

4 · Liste de prix (PDF, CSV, image de grille)

Aligné sur Commercial / grille prix_vente. Thomas propose des lignes de prix (culture, canal, prix, unité) à accepter une par une ou en lot. Une vente n’écrit pas la grille (déjà décidé Co1) ; une liste de prix, elle, vise la grille — toujours avec confirmation.

  3. L’agriculteur confirme tout, une sélection, ou annule. Rien n’écrase la grille sans ça.
  4. Le fichier est rangé en document (catégorie rapports ou autre / libellé « Liste de prix ») avec lien vers le lot appliqué.

Décidé (D1–D8)

D1 · Deux couches. Pièces jointes (liées) + documents de ferme (registre) + objets métier. Une vérité par objet.
D2 · Agent-first. Ajout principal via chat (ou upload registre qui passe le même pipeline). Confirmation avant écriture structurée.
D3 · Formats v1. Images + PDF + CSV (XLSX best-effort). Pas de vidéo.
D4 · Analyse de sol. Fichier → carte analyse (catalogue large : texture, pH, MO, CEC, majeurs, oligos, ETM…) + document analyse-sol. Voir Sol (S1–S3).
D5 · Liste de prix. Fichier → propositions grille prix_vente confirmées. Une vente ne modifie pas la grille.
D6 · Factures. Sortante = vente ; entrante = reçu/achat léger + document. Pas de compta (Cp1).
D7 · Registre Documents. Nav Ressources · liste / fiche / filtres · liens vers objets.
D8 · Ambiguïté. Type flou → question à choix, pas d’extraction inventée.
D9 · Facile vs complexe. Photo / analyse = parcours court. CSV planif / archive logiciel = rapport d’import + confirmation par lot. Même pipeline de vérité.
D10 · Nav. Documents est une entrée du sommaire et de la nav Ressources (coquille).
