Itinéraires & coûts culture · décidé

Fiche culture, ITK de base, série adaptée, coûts réels.

Chaque culture a une fiche. Un itinéraire technique (ITK) de base décrit le cycle type. Une série concrète (plan) en dérive une adaptation. Les temps de travail confirmés alimentent l’ITK réel et le coût de la culture. Basile Pro sert d’exemple métier — on ne porte pas son code.

Chaîne décidée. Fiche culture → ITK de base → série / plan adapté → tâches temps confirmées → ITK réel → coût culture. Dashboard : coûts temps par culture + charges hors temps. Amortissements cadrés, éventuellement différés en v1.

Fiche culture · décidé

Objet catalogue de la ferme (et/ou du catalogue partagé), distinct du plan de l’année. Une fiche = une culture cultivable (ex. laitue, tomate, pommier).

BlocContenu
IdentitéNom, aliases / mots-clés chat, filière, famille botanique optionnelle
UnitésUnités de vente et de production usuelles (kg, botte, plant, caisse…)
ITK de base liéRéférence à l’itinéraire type (ou plusieurs variants : serre / plein champ)
VariétésListe optionnelle ; une variété peut surcharger densités / durées
Charges typesPostes hors temps indicatifs (semences, engrais, pots, terreau…) — montants éditables

Sur ordi : galerie + fiche. Sur téléphone : lecture courte via chat (« fiche laitue ») — pas d’éditeur riche mobile (aligné P5 planification).

Accès UI · décidé. Pas d’entrée nav « Cultures / ITK ». Ouverture via Documents et via planification de culture (+ chat). Inventaire : Navigation · ITK.

ITK de base · décidé

Référence Basile : bibliothèque Itinéraires (Configurer). En V3 : entité structurée itineraries + gestes type itinerary_task_templates. Ce n’est pas du RAG flou seul — c’est de la mémoire métier structurée.

ÉlémentRôleExemple laitue
Phases / duréesPépinière, culture, récolte (semaines)Base : ~12 semaines cycle type serre
FenêtresSemaines / mois de semis, plantation, récoltePlantable janvier–octobre selon créneau
Gestes typesTemplates : irriguer, biner, récolter… avec ordre relatifIrrigation régulière ; 1ère récolte à J+X
Densités / rendementsIndicatifs pour projectionPlants / m² ; kg ou têtes / m²
Intrants typesLiens optionnels semences, engrais, potsDose type engrais / m²
Lecture agent. « Quel itinéraire laitue serre ? » → Thomas décrit le cycle à partir de l’ITK de base. Il ne crée un plan que si l’agriculteur le demande (intention déjà listée en fondation).

Adaptation à la série · décidé

Une série = un plan concret de l’année (objet plans, voir Planification). Elle part de l’ITK de base et le dérive.

Laitue ITK base 12 semaines. Plantée en février → série adaptée ~13 semaines, irrigation renforcée (froid / croissante).

NiveauObjetQui écrit
ITK de baseitinerariesCatalogue ferme / import ; éditable ordi
Série adaptéeplans (+ overrides durées, gestes, irrigation…)Chat (carte) ou modal plan ordi
ITK réelAgrégat calculé des tasks liées au plan / cultureCode après confirmations temps — pas une saisie libre
  1. L’agriculteur place une série (chat ou ordi) en choisissant culture + ITK (+ variété, lieu, semaine).
  2. Thomas propose les durées / gestes de l’ITK ; l’agriculteur ajuste (ex. +1 semaine, irrigation différente).
  3. Les gestes projetés (P2, optionnel) deviennent des tâches en_attente liées au plan.
  4. Chaque tâche faite confirmée (T-01) enrichit l’ITK réel de cette série / culture.

Temps de travail → ITK réel → coût · décidé

Aligné sur Temps : une ligne tasks confirmée porte durée, personnes, culture, lieu, plan si connu.

ÉtapeRègle
Temps saisiChat T-01 ou calendrier → tasks confirmée / cochée
RattachementCulture (plants) + plan ouvert si identifiable ; sinon agrégation par culture / parcelle
ITK réelSomme person_minutes (ou personnes × durée) par geste / phase / culture / série
Coût tempsEffort × taux horaire ferme (paramètre compte / ferme) → coût main-d’œuvre de la culture
ÉcartITK réel vs templates ITK de base / série (lecture dashboard + chat)
Exemple. Laitue serre 1, série S6 : 4 h désherbage + 6 h récolte (confirmées) → ITK réel = 10 h · coût = 10 × taux. L’ITK de base prévoyait 8 h → écart +2 h visible sur la fiche culture / dashboard.

Dashboard coûts · décidé

Vue ordi (et lecture agent) par culture / série / campagne.

FamillePostesv1
Coûts temps de travail Somme effort confirmé × taux ; détail par geste / phase Oui — cœur du premier lot
Charges hors temps Semences, engrais, pots, terreau, autres intrants saisis ou issus de factures entrantes légères Oui — saisie / lien document ; pas de compta complète
Amortissements Serre, matériel, irrigation… Cadrés dans le modèle ; peuvent être négligés / différés en v1 (pas bloquants)

Le dashboard n’invente pas de montants : il agrège les tâches confirmées et les charges enregistrées. Une charge sans montant reste un poste à compléter.

Données (aperçu)

Détail colonnes dans Données.

  • crops / fiche culture ferme — identité, ITK liés, charges types.
  • itineraries + itinerary_task_templates — base Basile-like.
  • plans — série adaptée (lien itinéraire, overrides).
  • tasks — temps réel ; agrégats coût côté lecture / vues.
  • crop_cost_items (à ajouter) — charges hors temps par culture / série / campagne.
  • Paramètre ferme : hourly_labor_rate (ou équivalent).

Décidé (I1–I6)

I1 · Fiche culture. Une fiche par culture ; ordi édite, tél lit via chat.
I2 · ITK de base. Entités structurées (pas RAG seul). Référence métier Basile.
I3 · Série adaptée. Le plan dérive l’ITK (ex. laitue 12 → 13 sem. + irrigation).
I4 · ITK réel. Issu des temps confirmés rattachés culture / plan.
I5 · Dashboard. Coûts temps + charges hors temps (semences, engrais, pots, terreau…).
I6 · Amortissements. Présents dans le modèle ; négligeables / différés possibles en v1.
