Données · brouillon (contrat vibe-coding)

Schéma aligné sur le produit. Une vérité par objet.

Cette page est le contrat entre le cahier et le code. Chaque entité cite ses colonnes produit, son statut (existe V2 / à ajouter / à adapter), et la règle d’écriture (confirmation chat ou dashboard). Pas de second modèle « pour l’IA » : l’état mince du harness lit ces tables, filtrées.

Règles transverses · décidé. (1) Toute écriture structurée issue du chat passe une carte confirmée. (2) Soft delete / is_active plutôt que purge immédiate. (3) Scope farm_id partout. (4) La filière ne duplique pas les tables — mêmes schémas, libellés différents. (5) Météo / conseil : pas de colonnes dans ce lot.

Fin de culture

plans.ended_on

décidé · date ; vide = plan ouvert. Semer / planter / implanter ouvre ou complète. Détruire / enlever / arracher propose la fin. Historique conservé.

Droits chat temps : choisir parcelle / sous-parcelle existantes ; recopier culture connue ; comparer au plan ouvert ; multi-activités = multi-lignes ; ne pas créer parcelle depuis T-01 (VAL_UNKNOWN_PLOT).

État mince — ce que le code charge pour un message

  1. Ferme + vue (soi / ferme / personne) + droits membre.
  2. Candidats : parcelles actives, sous-parcelles / planches des plans ouverts, cultures / plans ouverts, membres, matériels, quelques prix.
  3. Fil courant (N derniers messages + cartes en attente).
  4. À la demande seulement : ITK, document, ePhy, résumé épisodique, agrégats coût.

Jamais : dump de toutes les tâches historiques, tous les documents, tout ePhy.
